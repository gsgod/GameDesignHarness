# 구현 계획 리뷰 · 2026-09-16

결론: **아래 필수 보완을 반영하면 v0.1 구현 진행 가능.** 사용자 요청의 순서인 공통 하네스 → Game_1 디자인 착수를 따른다. 준거는 상위 Steam 개발 규칙 1.0.0의 R03/R06/R08/R11이다.

## 필수 수정과 반영

1. 상위 최신 소스를 직접 실행하면 한 게임 수정이 다른 게임을 바꾼다. 게임은 `releases/<version>`와 manifest SHA-256을 잠그고 전체 파일을 검증한다.
2. 공유 출력 폴더는 작품 간 충돌과 원본 손실을 만든다. 원본은 게임의 `art/source`, 후보는 게임의 `builds/design`, 반입은 게임 내부의 해시별 새 디렉터리다. 덮어쓰기와 런타임 심볼릭 링크를 사용하지 않는다.
3. 자동 검사 합격을 좋은 그림 또는 사용자 승인으로 오인할 수 있다. 기술 검사 / 엔진 PNG 읽기 / 사람의 미술 검토를 구분한다. 마지막 승인은 검토자·내용·로컬 증거 해시가 필요하다.
4. 승인 이후 이미지나 요구사항이 바뀌면 구 승인이 재사용될 수 있다. 입력 원본·편집 원본·참조 문서·도구·릴리스와 전체 후보 출력으로 digest를 묶고 매번 재검사한다.
5. 무료 편집 프로그램이 원화의 자동 생산을 의미하지 않는다. 처음은 Pixelorama/Krita 수동 export 수용 + 자동 검증이다. 생성 AI·유료 API·설치 다운로드는 하지 않는다.
6. 역사 장르를 코어에 고정하면 범용 목적이 깨진다. `project/pack`과 자산 계약만 공유하고 역사 검토는 Game_1 명세에 둔다. 비역사 퍼즐 fixture로 확인한다.
7. 요구사항에 명령어를 넣으면 임의 실행과 경로 이탈이 가능하다. 명령어 필드는 실행하지 않는다. 명시적으로 구성한 로컬 실행 파일과 고정 인수만 사용하고, 외부/상위 경로·심볼릭 링크·과대 입력을 거부한다.

## 권장 사항 / 다음 버전

- Pixelorama 버전별 실제 CLI 확인 후 native export 어댑터 추가. 지금 구현했다고 표시하지 않는다.
- atlas packing, 텍스처 용량 예산, 인게임 golden image 비교는 게임별 실제 요구를 받은 뒤 구현한다.
- 다른 운영체제의 도구 잠금과 CI 환경은 별도 실기기 검증 후 지원 표시한다.
- 출처는 기록과 검토 상태를 강제할 뿐 저작권 합법성을 자동 판정하지 않는다.
- 반복 실행은 완료된 동일 입력을 캐시 재사용한다. 중단된 개별 이미지 작업부터 재개하는 세부 checkpoint는 후속이다.

## 이번 완료 기준

공통 CLI/입력 계약/후보 출력/승인 및 로컬 반입/릴리스 잠금과 격리 테스트, Game_1 실제 연결과 제작 계획 생성. Game_1의 원화 미작성 상태에서 가짜 승인이나 색상 변경으로 미술 완성을 주장하지 않는다. Game_1의 디자인 착수 결과는 `design/art-direction.md`, `design/production-plan.md`, `design/requirements.json`에 남긴다.
